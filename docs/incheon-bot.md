# 인천공항 의전(Meet & Greet) 정보 텔레그램 봇

편명 하나만 입력하면 **IB(입국) / OB(출국)를 자동 판별**해 의전 담당자가 필요한 동선을 한 장으로 보여주고,
`book` 으로 등록한 편은 게이트·카운터·수취대·운항현황 변동을 자동으로 알려줍니다.

```
WE501                          → 오늘자 WE501 브리핑 (IB/OB 자동 판별)
WE501 0908                     → 9월 8일자
/book WE501                    → 변동 알림 + 사전 알림 시작
/memo WE501 VIP 3명, 휠체어 1대  → 메모 저장 (브리핑·알림에 함께 표시)
/remind WE501 90 차량 배차 확인  → 출발 90분 전 지정 알림
/done WE501                    → 알림 종료
```

## 무엇을 보여주나

**IB (입국)** — 도착 게이트 → 입국심사대 → 수하물 수취대 → 입국장 출구
- 입국심사대는 API 의 **출구(exitNumber) 를 1순위**로 안내합니다 (예: `출구 A · T2 동편 입국심사장`).
  출구가 아직 배정되지 않은 동안에는 도착 탑승구 구역으로 추정하고, 추정임을 명시합니다.
  `/book` 중이면 출구가 확정되는 순간 알림이 갑니다.

**OB (출국)** — 체크인 카운터 → 보안심사대(출국장) → 라운지 → 탑승구
- 보안심사대는 **실시간 혼잡도 API**로 대기시간을 받아 `도보시간 + 대기시간`이 가장 짧은 출국장을 추천하고,
  **인근 출국장의 혼잡도를 함께** 표시합니다.
- 가장 가까운 출국장이 혼잡해 추천이 달라진 경우 그 사실을 문구로 알려줍니다.
- 라운지는 항공사 → 얼라이언스(Star / SkyTeam / oneworld) → 자사 계약 순으로 `config/lounges.yml` 에서 조회합니다.

## 사용하는 공공데이터 API

| 용도 | 엔드포인트 | 일일 한도 |
|---|---|---|
| 항공기 운항 현황 상세 (도착) | `/B551177/statusOfAllFltDeOdp/getFltArrivalsDeOdp` | 500 |
| 항공기 운항 현황 상세 (출발) | `/B551177/statusOfAllFltDeOdp/getFltDeparturesDeOdp` | 500 |
| 출국장 혼잡도 (T1) | `/B551177/statusOfDepartureCongestion/getDepartureCongestion` | 1000 |
| 출국장 혼잡도 (T2) | `/B551177/statusOfDepartureCongestionT2/getDepartureCongestionT2` | 1000 |

운항 정보는 **조회일 기준 -3일 ~ +6일**만 제공되며, 그 밖의 날짜는 입력 단계에서 거절합니다.

## 설치 및 실행

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # TELEGRAM_BOT_TOKEN, DATA_GO_KR_SERVICE_KEY 입력
PYTHONPATH=src python -m incheon_bot
```

`.env` 주요 항목

| 변수 | 설명 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | @BotFather 발급 토큰 |
| `DATA_GO_KR_SERVICE_KEY` | 공공데이터포털 일반 인증키 (**Decoding 키** 권장) |
| `ALLOWED_USER_IDS` | 접근 허용 텔레그램 사용자 ID. 비우면 전체 공개 — 운영 시 반드시 설정 |
| `IIA_FLIGHT_DAILY_BUDGET` | 운항 API 하루 호출 상한 (기본 450, 한도 500 대비 여유) |
| `IIA_CONGESTION_DAILY_BUDGET` | 혼잡도 API 하루 호출 상한 (기본 900) |

인증키는 **절대 저장소에 커밋하지 마세요.** `.env` 는 `.gitignore` 에 포함되어 있습니다.

### BotFather 명령어 등록 (`/setcommands`)

```
start - 사용법 보기
flight - 편명 조회 (예: /flight WE501 0908)
book - 변동 알림 + 사전 알림 등록
memo - 항공편 메모 추가/조회/삭제
remind - 사용자 지정 사전 알림 (예: /remind WE501 90 차량 확인)
done - 알림 종료 (all 로 전체 종료)
list - 감시 중인 항공편 목록
congestion - 출국장 실시간 혼잡도 (T1/T2)
lounge - 항공사/얼라이언스 라운지
reload - 설정 파일 다시 읽기
status - API 사용량 및 감시 현황
cargo - 화물편 조회
```

한글 입력도 지원합니다: `혼잡도 T2`, `라운지 KE`, `감시 WE501`, `완료 WE501`,
`메모 WE501 VIP 3명`, `알림 WE501 90 차량 확인`.

## 사전 알림

`/book` 으로 등록하면 변동 알림과 함께 **예정시각 기준 사전 알림**이 자동으로 시작됩니다.
기본값은 `config/reminders.yml` 에 있고 `/reload` 로 즉시 반영됩니다.

| 구분 | 시점 | 내용 |
|---|---|---|
| OB | T-4h | 체크인 카운터 배정 확인 |
| OB | T-3h | 고객 미팅 / 공항 도착 |
| OB | T-2h | 보안심사 진입 권장 — **당시 혼잡도 기준 추천 출국장 동봉** |
| OB | T-1h | 탑승구 이동 |
| OB | T-40m | 탑승 시작 예정 |
| IB | T-90m | 입국 의전 준비 (미팅보드·차량) |
| IB | T-30m | 착륙 임박 — 도착 게이트·출구 확인 |
| IB | 착륙 +20m | 입국장 출구에서 대기 |

- **지연되면 아직 보내지 않은 알림은 변경시각 기준으로 자동으로 밀립니다.**
- 이미 시점이 지난 알림은 보내지 않습니다. 출발 30분 전에 등록해도 지난 알림 4건이 한꺼번에 오지 않고,
  유효한 T-40m 알림만 발송됩니다 (유예시간 `catch_up_minutes`, 기본 20분).
- 사용자 지정 알림: `/remind WE501 90 픽업 차량 배차 확인` (음수는 도착 후 — `/remind AK1623 -30 …`).
  `/remind WE501` 로 목록, `/remind WE501 취소` 로 전체 취소. 지정 알림도 지연에 따라 함께 밀립니다.
- 알림에는 해당 편 **메모가 함께** 표시됩니다.

## 메모

항공편에 자유 메모를 붙여 브리핑과 사전 알림에 함께 띄웁니다. `book` 여부와 무관하게 유지되고,
`(대화방, 편명, 날짜)` 단위로 분리 저장되므로 담당자별·일자별로 섞이지 않습니다.

```
/memo WE501 VIP 3명, 휠체어 1대       메모 추가
/memo WE501                          메모 보기
/memo WE501 삭제                     전체 삭제
/memo WE501 삭제 2                   2번 메모만 삭제
```

## book(자동 업데이트) 동작

- 감시 항목 — OB: 체크인 카운터 · 탑승구 · 터미널 · 예정/변경 시각 · 현황 / IB: 도착 게이트 · 수하물 수취대 · 입국장 출구 · 터미널 · 시각 · 현황
- 변동이 생긴 항목만 `이전 → 현재` 형태로 전송하고, 출국편의 카운터·탑승구가 바뀌면 **추천 출국장을 다시 계산해 함께** 보냅니다.
- 확인 주기는 출발/도착 시각까지 남은 시간에 따라 자동 조절됩니다 (8시간 초과 20분 → 3시간 5분 → 1시간 이내 2분).
  일일 호출 한도를 지키기 위한 설계이며, 소진 시 30분 뒤로 자동 연기합니다.
- 결항/취소는 즉시, 출발·도착 완료는 예정시각 +90분 후 감시를 자동 종료합니다. `/done` 으로 언제든 수동 종료할 수 있습니다.

## 운영 전 반드시 보정해야 하는 설정

두 API 모두 **터미널 내부 동선·라운지 정보를 제공하지 않습니다.** 아래 두 파일은 공개 배치도를 근거로 한
초기 기본값이므로, 현장 기준으로 검증한 뒤 운영에 투입하세요. `/reload` 로 봇 재시작 없이 반영됩니다.

- `config/routing.yml`
  - 체크인 카운터(A~M / A~H)·탑승구 구간·출국장의 상대 위치(`pos`, 동편 0 ~ 서편 100)와 도보 환산 계수
  - 도착 탑승구 구간별 입국심사장(동/서편) 라벨 — API가 주지 않는 값이라 이 매핑으로 안내합니다
  - 혼잡도 4단계 기준(원활 20분 미만 / 보통 20~40 / 혼잡 40~60 / 매우혼잡 60분 이상)은 제공기관 명세 그대로입니다
  - **`arrival_exits`** — 입국장 출구(A~F / A~B) → 입국심사장(동/서편) 매핑. 입국심사대 안내의 근거입니다
- `config/lounges.yml`
  - 항공사 → 얼라이언스 매핑, 라운지 위치·운영시간·이용 조건, **자사 별도 계약 라운지**
- `config/reminders.yml`
  - 사전 알림 시점과 문구. 의전 운영 절차에 맞게 시점을 조정하세요

## 구조

```
src/incheon_bot/
  settings.py           환경변수 설정
  service.py            항공편 1건 → 의전 브리핑 조립 (IB/OB 분기)
  watcher.py            book 등록 편의 주기 확인 및 변동 알림
  api/client.py         공공데이터 API 클라이언트 (TTL 캐시 + 일일 호출 버짓 + XML/JSON/평문오류 처리)
  api/models.py         Flight / Congestion 정규화
  domain/query.py       "WE501 0908", "KE86 내일" 등 자유입력 파싱
  domain/routing.py     터미널 동선 설정, 출국장 최적 경로 계산
  domain/lounges.py     얼라이언스·계약 라운지 조회
  domain/reminders.py   사전 알림 규칙 (지연 시 자동 재계산, 지난 알림 스킵)
  domain/status.py      현황 해석, 변동 비교, 적응형 확인 주기
  bot/handlers.py       텔레그램 명령·버튼 처리
  bot/formatting.py     메시지 렌더링 (HTML 파스모드)
  storage/db.py         book 상태 · 메모 · 지정 알림 SQLite 저장소 (컬럼 자동 마이그레이션)
```

## 테스트

```bash
python -m pytest
```

외부 호출은 `httpx.MockTransport` 로 대체해 네트워크 없이 전부 실행됩니다.
응답 명세표와 샘플 payload의 키 표기가 다른 점(`scheduleDatetime` vs `scheduleDateTime`),
`waitTime` 의 `60+` 표기, 출국장 미운영, 포털의 평문 오류 응답 등을 회귀 테스트로 고정해 두었습니다.

## 알려진 제약

- 인천공항 이외 공항, 국내선 연결편 동선은 다루지 않습니다.
- 입국심사대(출구 → 심사장 매핑)·라운지 위치는 API가 아닌 설정 파일 기반이라 터미널 리모델링 시 수동 갱신이 필요합니다.
- 사전 알림은 감시 주기(최소 1분, 시각이 가까울수록 촘촘) 위에서 동작하므로 분 단위로 오차가 있을 수 있습니다.
- 코드셰어편은 마스터 편명으로도 조회되며, 결과에 운항사 편명을 함께 표시합니다.
